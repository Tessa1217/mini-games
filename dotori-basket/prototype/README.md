# 프로토타입

```bash
cd squirrel-basket-game
python3 -m http.server 8742
# → http://127.0.0.1:8742/prototype/index.html
```

`file://`로 열면 안 된다 — 에셋을 상대 경로로 불러오므로 서버가 필요하다.

## 화면 흐름

```
로딩(프리로드) → 타이틀 ⇄ 놀이법 → 게임 ⇄ 해금 카드
                                    ⇅
                                 일시정지 → 계속 / 다시하기 / 처음 화면
                                    ↓
                                 게임 오버 → 다시하기 / 처음 화면
```

**일시정지** — HUD 우측 상단 버튼, 또는 `Esc` · `P` 키로 토글한다.
`document.hidden`이 되면(탭 전환·앱 전환) **자동으로 멈춘다** — 웹뷰에서 앱을 바꿨다가
돌아왔을 때 그 사이 판이 진행돼 있으면 안 되기 때문이다. `pagehide`에서도 같이 건다.

`PHASE` 상태 기계가 관리하고, `step()`은 `'playing'`일 때만 게임을 전진시킨다.
**해금 카드는 게임을 멈춘다** — 과일이 떨어지는 중에 띄우면 읽을 수가 없다.
2.2초 뒤 자동 해제되고, 탭하거나 Enter/Space로 즉시 재개할 수 있다.

레벨업 알림은 두 갈래다.

- **해금이 있는 레벨**(Lv2 포도 · Lv3 수박+방해물 · Lv4 배 · Lv5 체리) → 카드를 띄우고 멈춘다.
  방해물은 «조심하세요»로 과일과 분리해 보여준다 — 받으면 도토리가 깎이는 것들이라
  같은 줄에 두면 안 된다.
- **해금이 없는 레벨**(Lv6·Lv7·무한 구간) → 멈추지 않고 배너만. 문구는 그 레벨에서 실제로
  바뀐 것을 말한다(레시피 길이 / 방해물 비율 / 속도). 매번 같은 말이면 읽지 않게 된다.

## 숲길 배경은 어떻게 만들었나

게임 화면의 배경(`bg.jpg`)은 **좌우 끝에만 나무가 있고 가운데가 비어 있다** — 과일 낙하 경로에
장식이 있으면 안 되기 때문이다. 그런데 로딩·타이틀·놀이법 화면은 떨어지는 게 없으므로
가운데가 빈 하늘이면 오히려 이질적이다.

그래서 **생성 없이 기존 배경에서 조립**했다 (`assets/scene/bg-forest-full.jpg`, 44KB).

1. 왼쪽 나무가 **줄기 바로 오른쪽에서 프레임에 잘려** 있다(줄기 x 0~31). x=0에서 미러링하면
   줄기 하나짜리 온전한 나무가 복원된다.
2. 하늘(`#C4E1F4`)과 잔디가 단색이라, 수평선 위/아래로 기준색을 나눠 키잉하면 나무만 깨끗이 떨어진다.
3. 뒤쪽 줄은 0.62~0.72배로 줄이고 하늘색을 18% 섞어 공기원근을 준 뒤, 앞쪽 줄을 겹친다.
4. 잔디와 수평선은 **중앙에서만 떼어** 쓴다 — 가장자리를 쓰면 원본 나무 밑동이 딸려 온다.
   타일은 **미러 타일링**(홀수 칸을 뒤집기)으로 이어 붙여 경계 행/열이 일치하게 했다.

재생성이 필요하면 이 순서를 그대로 밟으면 된다. SpriteCook은 쓰지 않는다.

## 난이도는 속도로 만든다

레인이 5개라 **화면에 몇 개가 더 떠도 피할 자리가 남는다** — 밀도는 난이도로 잘 안 바뀐다.
그래서 밀도는 2.80으로 고정하고 낙하 속도만 올린다.

계기판의 **회피여유** = 낙하시간 − 4칸 × `moveCooldownMs`, 즉 *끝에서 끝까지 피하고 남는 시간*.
이게 레벨업 체감을 만드는 값이다.

```
Lv1  낙하 2.50s  회피여유 2.02s
Lv4  낙하 1.45s  회피여유 0.97s
Lv7  낙하 0.95s  회피여유 0.47s
```

`fallSpeedMax`(0.65초)가 상한인 이유도 같다 — 4칸 이동에 0.48초가 필요하므로
그 아래로는 회피 자체가 불가능해진다.

## 다람쥐 정렬 — 바운딩 박스가 아니라 몸 축 기준

다람쥐는 **꼬리가 오른쪽으로 뻗어** 있어서 바운딩 박스의 중심과 몸의 축이 어긋난다.
실측(`assets/generated/squirrel.png`, 폭 729):

```
바구니 중심   박스 중심 대비 −101.5px
발   중심     박스 중심 대비 −103.0px     → 몸 축 = 폭의 35.9%
```

박스를 레인 중심에 맞추면 **정작 바구니가 11.5px 왼쪽으로 치우친다**(82px 기준).
판정은 바구니에서 일어나므로 몸 축을 레인 중심에 맞춘다.

- CSS 토큰 `--sq-axis: 35.9%` — 타이틀 히어로 이미지와 기울기 회전 축(`transform-origin`)에 쓴다
- 게임 좌표는 `SQ_AXIS`/`SQ_OFF` 상수로 보정한다

**스프라이트를 교체하면 이 값을 다시 재야 한다.** 상단 22%(바구니)와 하단 12%(발)의
불투명 픽셀 범위를 구해 중심을 평균 내면 된다.

## 테스트 훅

URL에 `?dbg`를 붙이면 `window.__dbg`가 열린다. 레벨업까지 손으로 가는 게 비싸서 넣었다.

```js
__dbg.jump(3)    // Lv3으로 올리고 해금 카드를 띄운다
__dbg.state()    // phase · level · hp · score · recipe · limit
__dbg.start()    // 새 판 시작
```

## 수치의 출처

`game/config/balance.ts`의 값을 스크립트 상단 `BAL` 객체에 **복사**해 두었다.
프로토타입은 TS를 못 읽으므로, **`balance.ts`를 고치면 여기도 같이 고쳐야 한다.**
Next 앱으로 옮길 때 `import { BALANCE }`로 대체되면서 이 중복은 사라진다.

아트가 없는 과일(레몬 이후 8종)은 목록에서 빠져 있어, 프로토타입의 과일 풀은 Lv7에서 멈춘다.

## 튜닝 패널

미정으로 남아 있던 두 가지를 직접 만져보라고 넣었다.

- **레시피 제한시간** — **고정 30초**. 역산식으로 두면 스폰이 몰릴 때 "정답이 안 나와서 지는"
  판이 생긴다. 최소소요가 5.4~6.3초라 30초면 정상 플레이에서 걸리지 않고, 안 받고 버티는
  회피 플레이만 막는다. 난이도는 타이머가 아니라 낙하 속도가 담당한다.
- **레벨당 레시피** — 레벨 하나가 몇 초짜리인가. 옆에 Lv1 기준 예상 시간이 뜬다. 기본 5개.
- **실패하면 이번 레벨을 처음부터** — 제한시간 초과 시 그 레벨의 진행도까지 되돌릴지.
  켜면 레벨업에 연속 성공이 필요해져 난이도가 크게 오른다. 기본 꺼짐.
- **이동 쿨다운** — `moveCooldownMs`. 줄이면 회피가 쉬워져 단순 받기 게임이 되고,
  늘리면 경로 판단의 비중이 커진다. 기본 120ms.
- **위치 보간** — 켜면 `docs/rules/lane.md` 불변식(시각 위치 === 논리 위치)을 일부러 깬다. 감각 비교용이다.
  끈 쪽이 정답이라는 게 설계 결론이지만, 실제로 느껴보고 확정하면 된다.

`낙하 속도 배율`은 레벨값을 덮어쓴다(기본은 레벨 표를 따름), `catchLineY 500 표시`는 판정선을 그린다.
