## 작업 1 — 실행 순서 ⭐

현재 git 저장소가 아니라 **모든 삭제가 복구 불가**다. 두 삭제는 제약이 정반대다.

- 스톡 원본·추적물 — 이력에 **들어가면 안 된다**
- `PLAN.md`·`DESIGN.md` — 삭제 전 **반드시 커밋돼야 한다**

```
1. git init + 저장소 단위 user.name/email + .gitignore(.DS_Store 포함)
2. 스톡 4개 삭제                              ← 커밋 전, 이력 진입 금지
3. 커밋①  "초기 — 기획 문서와 설정"           ← PLAN·DESIGN 원형 보존
4. 4a ⭐표기 통일 → 4b 문서 분할 → 4c 상수 분할 → 4d CLAUDE.md
     (4d의 불변식 표는 4a의 ⭐를, 라우팅 표는 4b의 파일명을 읽어야 채울 수 있다)
5. 커밋②  "문서 분할 + 컨벤션"
6. PLAN.md·DESIGN.md 삭제 → 커밋③             ← 이제 복구 가능
```


`BalanceConfig`의 키는 **9개**(`lane movement hp scoring recipe spawner levelUp levels endless`).
초안은 `levelUp`을 빠뜨리고 멤버 아닌 `items`를 넣었다.

**타입 고정 필수** — 분할하면 `rulePriority`가 `string[]`로 넓어져 조립 시 에러가 난다.
```ts
export const spawner = { … } satisfies SpawnerConfig      // 9개 조각 전부
export const levels: LevelTuning[] = [ … ]                // levels만 예외 (readonly 아님)
export const BALANCE: BalanceConfig = { lane, movement, hp, scoring, recipe,
                                        spawner, levelUp, levels, endless }
```
`tuning.ts`는 `BALANCE.levels`를 직접 읽는 **유일한 정당 소비자**다 — CLAUDE.md 규칙에 단서를 단다.

「15% 이하」는 작은 파일에 적대적이고(8줄 파일에서 1줄=12%), 지우면 안 되는 주석을 지운다.

| 남긴다 | 이유 |

| `simultaneousCrossLimit` ← `lane.count - 2` | **파생 관계** — 문서로 보내면 레인을 6으로 바꿔도 3이 남아 회피 보장이 깨진다. **코드로 표현**한다 |
