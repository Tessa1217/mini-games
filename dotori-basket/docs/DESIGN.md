## 0. 무드 원칙 — 동물의 숲

| 원칙 | 구체적으로 |
|---|---|
| **순수 검정을 쓰지 않는다** | 텍스트·아웃라인 모두 따뜻한 브라운 계열(`#5A4632`). 검정은 이 무드를 즉시 깬다 |
| **채도를 낮춘다** | 원색 금지. 모든 색이 약간 바랜 듯한 톤 |
| **모서리를 둥글게** | 직각 없음. 카드 16px, 칩 10px, 버튼 원형 |
| **그림자는 갈색 알파** | `rgba(90,70,50,.12)` — 회색 그림자는 차갑게 읽힌다 |
| **선이 아니라 면** | 굵은 아웃라인 대신 면과 부드러운 명암으로 형태를 만든다 |
| **움직임은 탄성** | 선형 이징 금지. 모든 전환에 약한 오버슈트 |

## 2. 레이아웃 — 논리 좌표 360 × 640 실측값

```
 y=0    ┌─────────────────────────────────────┐
        │  HUD                                │
        │  ● ● ●        Lv.3          1,240   │  Row1  y 14~38
        │  ┌──────────────┐  ×2.0    ┌────┐   │  Row2  y 44~88
        │  │ 🍓 →🍎 →🍊  │          │ ⏸ │   │
        │  └──────────────┘          └────┘   │
 y=90   │ ████████████████████░░░░░░░░░░░░░░  │  타이머 바  y 90~96
 y=96   ├──┬──┬──┬──┬──────────────────────┤
        │  │  │🍎│  │  │                     │
        │  │  │  │  │  │   스테이지           │
        │  │🍇│  │  │  │   레인 5 × 72px      │
        │  │  │  │🍓│  │                     │
 y=500  ├──┴──┴──┴──┴──┤ ← 판정선 = 잔디 상단 │
        │      ╭───╮                          │  바구니 y500~526
        │      │🐿️│      다람쥐               │  다람쥐 y522~572
 y=572  │  ╭───╮       ╭───╮                  │
        │  │ ◀ │       │ ▶ │  컨트롤 바        │  버튼 ⌀60, 중심 y606
 y=640  └──┴───┴───────┴───┴──────────────────┘
```

| 영역 | y 범위 | 비고 |
|---|---|---|
| HUD | 0 ~ 96 | 좌우 패딩 16 |
| ├ Row1 | 14 ~ 38 | HP(좌) · 레벨(중앙) · 점수(우) |
| ├ Row2 | 44 ~ 88 | 레시피 큐(x16~236) · 콤보(x244~292) · 일시정지(x300~344, 44×44) |
| └ 타이머 바 | 90 ~ 96 | 높이 6, 전체 폭, 좌→우 감소 |
| 스테이지 | 96 ~ 500 | 레인 5 × 72px (x 0/72/144/216/288) |
| **판정선** | **500** | 선을 그리지 않는다 — **잔디 상단 가장자리가 그 역할** |
| 다람쥐 | 500 ~ 572 | 바구니 상단이 정확히 y500 |
| 컨트롤 바 | 572 ~ 640 | 버튼 ⌀60(시각) / 72×72(터치 영역), 중심 x 56 · 304 |

### 2-1. ⚠️ 컨트롤 바가 세로로 분리된 이유 (밸런스에 영향을 준 결정)

버튼을 다람쥐 **좌우**에 두려 했으나, 5레인이 전체 폭을 쓰므로 레인 0·4에 있는 다람쥐와
**46px 겹친다**. 세로로 분리하는 수밖에 없고, 그만큼 판정선이 올라간다.

→ `catchLineY` **540 → 500**, 낙하시간을 유지하기 위해 `baseFallSpeedPxPerSec` **180 → 167**
(500/3.0), `sameLaneMinGapPx` **190 → 175**. 밀도 곡선은 그대로다(2.00 → 4.86, 재검증 완료).

**디자인이 밸런스 수치를 바꾼 사례**이므로 기록해둔다. 앞으로도 레이아웃 변경 시
`catchLineY`가 바뀌면 `baseFallSpeedPxPerSec`를 같은 비율로 보정해야 낙하시간이 유지된다.

### 2-2. 스케일링

```
scale = min(viewportW / 360, viewportH / 640)     ← contain
```
19.5:9 같은 긴 화면에서는 위아래 여백이 생기는데, **레터박스를 보이지 않게** 한다 —
컨테이너 뒤에 같은 하늘/잔디 그라디언트를 깔아 화면 끝까지 흐르게 한다.
`cover`로 잘라내면 판정선(y500 고정)이 화면 밖으로 나갈 수 있으므로 쓰지 않는다.

safe-area는 논리 좌표 **밖**에서 처리한다 — 컨테이너에 `padding: env(safe-area-inset-*)`.
논리 좌표 안에 넣으면 기기마다 판정선 위치가 달라진다.

## 4. 아이템 형태 시스템 — 색이 아니라 실루엣으로 구분

`PLAN.md` §5-4가 "색만으로 구분 금지"를 요구한다. 8종까지 늘어나므로 **실루엣만으로 판별
가능**해야 한다. 각 아이템에 고유한 형태 축을 하나씩 배정한다.

| 아이템 | 색 | 형태 축 (고유 식별자) | 크기 |
|---|---|---|---|
| 🍓 딸기 | `#F0607E` | **역삼각형** + 씨점 + 초록 꼭지 | S (36) |
| 🍎 사과 | `#DC4A3D` | 원 + **상단 패임** + 잎 1장 | M (42) |
| 🍊 귤 | `#F3A353` | **완전한 원** + 납작한 꼭지 (가장 단순 = 귤) | M (40) |
| 🍐 배 | `#C9D98F` | **눈사람형** (아래가 넓은 서양배) | M (44) |
| 🍇 포도 | `#8E6FB5` | **알 여러 개 뭉치** (유일한 다중 형태) | M (44) |
| 🍑 복숭아 | `#F5A7A0` | 원 + **중앙 세로 홈** + 잎 2장 | M (42) |
| 🍋 레몬 | `#F7DC4F` | **가로 타원 + 양 끝 뾰족** | S (38) |
| 🍉 수박 | `#6CAE6B` | **가장 큰 원** + 줄무늬 | L (52) |
| 🪨 돌멩이 | `#8D8A84` | **각진 다각형** (유일한 직선 형태) | M (40) |
| 🪵 나뭇가지 | `#8A6B4F` | **가로로 긴 막대** + 잔가지 | 가로 56×20 |

**검증**: 위 10색의 CIE ΔE 최소값은 **21.3**(돌멩이↔나뭇가지)으로 전 쌍이 20을 넘는다.
가장 가까운 그 두 개가 형태 차이는 가장 크므로(각진 덩어리 vs 가로 막대) 실사용 구분은 안전하다.

**방해물 2종의 시각 규칙**: 과일과 즉시 구분되도록 **각진 실루엣 + 낮은 채도 + 무채/갈색**.
"먹을 수 없는 것"이 형태만으로 읽혀야 한다. 광택(specular highlight)을 주지 않는다 —
과일에만 광택을 넣어 "먹을 수 있음"의 시각 언어로 삼는다.

> 초기 구현은 이모지 플레이스홀더로 진행하되, 🍐/🍋은 이모지 실루엣이 비슷하므로
> 플레이스홀더 단계에서도 **배경 원의 색으로 보조 구분**한다.

### 4-1. ⚠️ 정정 — 아이템에 림(테두리)이 필요하다

**형태 축만으로는 부족했다.** 아이템 색과 하늘색의 WCAG 대비를 실측한 결과,
기본 테마에서 **10종 중 9종이 3:1 미만**이었다(배 1.0 · 레몬 1.1 · 복숭아 1.3 · 귤 1.4).
파스텔 과일 + 밝은 하늘은 구조적으로 대비가 나오지 않는다.

→ **모든 아이템에 얇은 림을 두른다.** 그러면 대비가 아이템 색이 아니라 **림 색**으로 결정된다.
채색은 그대로 수채이고 테두리만 얹는 **펜과 수채(ink & wash)** 방식이라 무드도 유지된다.

**림 색은 고정값이 아니라 테마 토큰(`--rim`)이다** — §14 참조.

### 4-2. 가로세로 비율 — 실측값을 따른다

손으로 그리면 **대부분 세로로 길어진다.** 실제 과일은 반대로 **가로가 넓은 것이 많다.**
비율이 틀리면 아무리 잘 칠해도 그 과일로 안 보인다.

| 아이템 | 실측 (폭:높이) | 적용값 | 근거 |
|---|---|---|---|
| 사과 | 1.12 | **1.15** | 폭 81.4mm × 높이 71.3mm |
| 귤 | 1.24–1.38 | **1.30** | 지름 60–68mm × 높이 46–49mm |
| 복숭아 | 1.18 | **1.22** | 가로 82.6mm × 축 69.9mm |
| 레몬 | 1.27 (길이:폭) | **1.37** | 길이 50–70mm × 폭 40–55mm |
| 딸기 | 세로가 김 | **1.19** (높이:폭) | 원뿔형 |
| 수박 | ~구형 | **1.08** | 세트에서 가장 큼 |

적용값은 선언이 아니라 **실제 경로를 `getBBox()`로 측정한 값**이다. 아트를 수정하면 다시 잰다.

**귤의 형태 축을 고쳤다**: "완전한 원" → **"납작한 원"**.
실제 귤은 눌린 것처럼 납작해서(지름이 높이의 1.3배), 둥글게 그리면 오렌지나 사과로 보인다.
납작하게 그리는 것만으로 "귤"이 된다.

**사과는 위아래가 모두 오목하다.** 꼭지 쪽만 파이고 아래를 둥글게 그리면 토마토처럼 보인다.
가장 넓은 지점도 중앙보다 **위**에 있다. 이 둘이 사과다움을 만든다.

### 4-3. 배 — 서양배로 확정

한국에서 "배"는 신고배 — **거의 완전한 구**에 황갈색이다. 현재는 **서양배(눈사람형)**로 그렸다.

| | 서양배 (현재) | 한국배 |
|---|---|---|
| 사실성 | 한국 플레이어에겐 낯설다 | "배"로 바로 읽힌다 |
| 실루엣 구분 | **유일한 눈사람형 — 즉시 구분** | 둥근 황갈색 = 귤과 실루엣 중복 |
| 게임 영향 | 없음 | **오답 유발 → HP 손실** |

**서양배로 확정한다.** 한국배로 바꾸면 색만으로 귤과 구분해야 하는데, 그게 §4에서 피하려던 상황이고
오답은 곧 HP 손실이다. 사실성보다 구분 가능성이 우선한다.

> 나중에 한국 정서를 더 살리고 싶으면, 배를 한국배로 바꾸는 대신 **감을 추가**하는 쪽이 낫다
> — 납작하고 주황이지만 꼭지가 크고 각져서 귤과 구분된다.

### 4-4. 칠하는 방식 — 한 아이템에 6개 층

단색 평면은 부피가 없어 인쇄물처럼 보인다. 아래 순서로 쌓는다.

| 층 | 역할 |
|---|---|
| 바탕색 | 아이템 고유색 (`items.ts` 값 그대로) |
| 그림자 | 우하단에 어두운 덩어리를 흐리게 — **둥근 부피**를 만든다 |
| 하이라이트 | 좌상단. 광원 방향은 전 아이템 동일(§0) |
| 물감 고임 | 실루엣 안쪽에 같은 색 진한 테두리 — 수채 특유의 가장자리 |
| 질감 | 딸기 씨 · 귤 유포 · 수박 줄무늬 · 포도 과분 · 나뭇가지 결 |
| **가변 선 굵기** | 그림자 쪽 윤곽만 **2.4 → 4.1**로 굵게 |

**가변 선 굵기가 체감 차이가 가장 크다.** 손으로 그린 선은 빛 받는 쪽이 가늘고 그늘진 쪽이 굵다.
전체를 같은 굵기로 두르면 그 순간 **스티커처럼** 보인다.

**방해물 2종만 하이라이트가 없다.** 돌멩이는 그라디언트 대신 **면마다 밝기가 끊기고**,
나뭇가지는 광택 없이 결만 넣는다 — 과일에만 광택을 주는 것이 "먹을 수 있음"의 시각 언어다.

부수 효과: 명암이 들어가면서 **흑백 구분이 좋아졌다.** 전에는 색을 빼면 비슷한 회색 덩어리였는데,
이제 밝기 분포가 서로 달라 형태 축과 함께 이중으로 구분된다.

## 5. 화면 5종

### 5-1. 타이틀
로고(나무 간판 형태) · 시작 버튼(크게, 중앙) · 최고 점수(간판 아래 작게) · 조작 안내(아이콘 2개).
배경은 플레이 화면과 동일한 숲 — 과일 몇 개가 아주 느리게 떨어지는 데모 낙하.

### 5-2. 플레이

**레시피 큐에는 실제 과일을 그린다.** 색 동그라미로 대신하면 안 된다 —
플레이어는 낙하물을 형태로 식별하는데(§4), 큐만 색으로 보여주면 **두 개의 다른 언어**를 쓰는 셈이라
매번 머릿속에서 변환해야 한다. 큐의 아이콘은 낙하하는 스프라이트와 **같은 에셋**이어야 한다.

현재 타깃만 1.16배 확대 + 불투명, 지난 항목은 흐리게(0.16), 남은 항목은 중간(0.38).
§2 레이아웃. **레시피 큐가 시선의 중심**이므로 가장 밝은 카드(`--cream`)로 띄우고
현재 타깃만 확대(1.15×) + 은은한 펄스.

### 5-3. 일시정지
배경 blur(8px) + 크림 카드. 계속 / 다시하기. 자동 일시정지(앱 전환)로 진입한 경우
"잠시 멈췄어요" 한 줄을 덧붙인다 — 사용자가 누른 게 아니므로 이유를 알려준다.

### 5-4. 레벨업 (1.5초)
중앙 배너 + 새 과일 아이콘이 회전하며 등장. **루프와 타이머가 정지**한다.
해금이 없는 레벨(Lv8+)에서는 배너 문구를 "레벨 8"로 바꾸고 아이콘 대신 레벨 숫자를 키운다.

### 5-5. 게임오버
최종 점수(크게) · 최고 기록 갱신 시 리본 · 도달 레벨 · 다시하기.
**갱신 여부로 연출을 분기**한다 — 갱신 시 리본 + 반짝임, 아니면 차분하게.

## 6. 연출 명세 (framer-motion 담당)

`PLAN.md` §6-1 불변식: **낙하 노드와 연출 노드를 분리한다.** 아래는 전부 이펙트 레이어의
일회용 노드에서 재생한다.

| 이벤트 | 연출 | 길이 |
|---|---|---|
| **정답 획득** | 과일 `scale 1→1.3→0` + `y −20`, 동시에 `+10` 플로팅 텍스트가 위로 뜨며 페이드 | 320ms |
| **오답 획득** | 과일이 `x ±40 · y −30 · rotate 90°`로 튕겨 나가며 낙하 소멸 + **화면 shake 4px** + HP 도토리 pop 후 회색 전환 | 400ms |
| **레시피 완성** | 큐 카드 전체 반짝 → 좌측 슬라이드 아웃, 새 큐 우측에서 인, 보너스 점수 팝 | 500ms |
| **레벨업** | 배너 `scale .8→1` 오버슈트 + 과일 아이콘 회전 등장 | 1500ms |
| **타이머 경고** | 바 색 `--accent → --danger` + 0.5s 주기 펄스 | 반복 |
| **다람쥐 이동** | 진행 방향으로 `rotate ±12°` + `squash(scaleX 1.08, scaleY .94)` 후 복귀 | 90ms (`snapTiltMs`) |
| **다람쥐 피격** | 0.8초 무적 동안 `opacity` 깜빡임 (6회) | 800ms |

**`prefers-reduced-motion`**: 화면 shake · 파티클 · 회전 제거. 페이드와 색 전환만 남긴다.
깜빡임(피격)은 **광과민성 위험**이 있으므로 이 모드에서 반드시 정적 테두리 표시로 대체한다.

## 12. 아트 방향 확정 — 2D 수채

시안 비교 결과 **선 없는 수채 방향**으로 확정했다.

| | 채택 |
|---|---|
| 매체 | **2D 수채** — 윤곽선 없이 색면으로 형태를 만든다 |
| 질감 | 가장자리가 물감처럼 번진다 (`feTurbulence` + `feDisplacementMap` + 미세 블러) |
| 렌더 | **2D 스프라이트 + DOM/CSS transform** → three.js 불필요 |

### 12-1. 렌더 전략에 미치는 영향

2D 스프라이트도 **평면 회전은 자유롭다.** 떨어지는 과일이 도는 연출은 CSS `transform: rotate()`로 충분하다.
잃는 것은 "회전할 때 빛이 표면을 따라 움직이는 것" 하나뿐이다.

→ **three.js를 넣지 않는다.** `PLAN.md` rev.5 §6(DOM + CSS transform · framer-motion은 연출 전용)이
원래 설계 그대로 유효하고, 번들 **116 KB(gzip)** 를 아낀다.

### 12-2. 선이 없어서 생기는 제약

선이 형태를 붙잡아주지 않으므로 **실루엣이 유일한 구분 수단**이 된다.
§4의 형태 축을 3D 시안보다 **더 강하게** 지켜야 하고, 특히 방해물 2종은
**채도를 과일보다 확실히 낮춰** 색으로도 한 번 더 갈라놓는다.

## 13. 동물 스킨

### 13-1. 원칙 — 머리만 교체한다

몸통·팔다리·바구니는 **모든 스킨이 동일한 에셋**을 쓴다. 동물마다 새로 그리는 것은 **머리 하나**뿐이다.

| 방식 | 4상태 × 5동물 아트 장수 |
|---|---|
| 전신을 매번 그림 | 20장 |
| **머리만 교체** | 몸 4장 + 머리 5장 = **9장** |

표정 변화(피격·환호)는 **눈·입만** 별도 레이어로 얹으면 머리 5장도 다시 그릴 필요가 없다.

**공유되는 건 '모양'이지 '색'이 아니다.** 몸 색상은 스킨 토큰(`--fur` · `--fur2` · `--belly`)으로
함께 바뀐다 — 모양은 그대로 두고 `fill`만 교체한다. 고양이가 다람쥐 몸 색을 달고 있으면 어색하다.

**꼬리는 머리와 한 세트다.** 동물마다 다르므로(다람쥐 큰 꼬리 · 너구리 줄무늬 · 토끼 솜꼬리 ·
고양이 가는 꼬리 · 곰 짧은 꼬리) 몸 공유 부품이 아니라 **스킨 부품**으로 묶어 관리한다.

### 13-2. ⚠️ 귀가 바구니 테두리보다 높으면 안 된다

**바구니 테두리가 판정선(`catchLineY`)이다.** 귀가 그보다 위로 올라가면 화면에서 가장 높은 지점이
귀가 되어, 플레이어가 **어디서 받아지는지 오인한다** — "귀에 닿았는데 왜 안 받아지냐"가 된다.

→ **토끼는 늘어진 귀(lop ear)로 잡는다.** 세운 귀는 이 게임에서 쓸 수 없다.
다른 동물의 귀도 바구니 테두리 높이를 넘지 않게 배치한다.

### 13-3. 스킨은 순수 외형이다

히트박스 · 바구니 폭 · 이동 속도 · 무적 시간은 **전부 동일**하다.
하나라도 다르면 "곰이 유리하다"가 되어 밸런싱이 스킨 수만큼 갈라진다.
동물별 특수 능력은 밸런스를 다시 짜야 하는 **별개 기능이므로 Phase 2**로 둔다.

### 13-4. 라인업 (초안)

| 스킨 | 귀 실루엣 | 해금 조건 ⚠️ |
|---|---|---|
| 다람쥐 | 작고 둥근 귀 + 큰 꼬리 | 기본 |
| 고양이 | 뾰족한 삼각 귀 + 수염 | 최고 점수 500 |
| 토끼 | **늘어진 긴 귀** | 최고 점수 1,500 |
| 너구리 | 둥근 귀 + 눈가 마스크 무늬 | 최고 점수 3,000 |
| 곰 | 크고 둥근 귀 + 넓은 얼굴 | 최고 점수 6,000 |

게임 크기(약 72px)에서 **귀 실루엣만으로** 구분돼야 한다. 무늬는 보조 수단이다.

### 13-5. 구현 — 지금은 구조만

| 항목 | 내용 |
|---|---|
| `game/config/skins.ts` | 스킨 정의 — id · 이름 · 해금 점수 · 머리 스프라이트 · 몸 색상 토큰 |
| 해금 판정 | 기존 `localStorage` 최고 점수와 비교 — **새 저장소 불필요** |
| 선택 UI | 타이틀 화면 가로 스크롤 선택기. 잠긴 것은 실루엣 + 해금 조건 표시 |
| 선택 저장 | `localStorage` (접근 자체가 throw할 수 있으므로 try/catch) |
| 게임 로직 | **변경 없음** — 렌더 레이어만 스킨을 읽는다 |

**해금 연출은 게임오버 화면에 붙인다.** 최고 점수를 갱신하는 순간이 곧 해금 순간이라,
그 화면에서 "새 친구가 늘었어요"를 보여주면 다시하기를 누를 이유가 하나 더 생긴다.
현재 이 게임의 재도전 동기는 점수 하나뿐이라 실질적인 보강이 된다.

## 14. 배경 테마

### 14-1. 림 색은 테마 토큰이다

밝은 테마는 어두운 림, 어두운 테마는 밝은 림이 필요하다. 고정하면 한쪽이 반드시 깨진다.

| 테마 | 하늘 | 림 | 림↔배경 대비 |
|---|---|---|---|
| 숲(기본) | `#A9D9E8` | `#5A4632` | 5.8 |
| 봄 벚꽃 | `#F7DCE6` | `#5A4632` | 6.9 |
| 여름 바다 | `#86D3EC` | `#5A4632` | 5.3 |
| 가을 단풍 | `#F6D9B0` | `#5A4632` | 6.6 |
| 겨울 눈 | `#E3EDF5` | `#5A4632` | 7.5 |
| 밤 반딧불 | `#2E3A5C` | **`#FFF6E3`** | 10.4 |

전부 3:1을 넘는다. 아이템 에셋은 하나이고 **림 색 토큰만** 바꾼다 — 다시 그리지 않는다.

### 14-2. 새 테마 승인 조건

테마를 추가할 때마다 아래를 통과해야 한다.

- [ ] **림↔하늘 대비 ≥ 3:1** (WCAG 비텍스트 기준)
- [ ] 위쪽 낙하 영역에 장식이 없다
- [ ] 지면 경계가 판정선(`catchLineY`)과 일치한다
- [ ] 낙하 입자가 **아이템 크기의 1/4 이하, 투명도 60% 이하**

### 14-3. ⚠️ 낙하 입자가 가장 위험하다

꽃잎·눈송이·낙엽이 아이템만큼 눈에 띄면 플레이어가 **반사적으로 받으러 간다.**
그건 곧 오답이고 HP 손실이다. 크기·투명도 상한을 못 박고,
`prefers-reduced-motion`에서는 정지시킨다(전정 자극·광과민성).

### 14-4. 해금 — 스킨과 다른 축

동물 스킨과 같은 조건으로 묶으면 한 번에 우르르 열려 보상이 몰린다. 축을 나눈다.

| 축 | 대상 | 기준 ⚠️ |
|---|---|---|
| 누적 실력 | 동물 스킨 5종 | 최고 점수 (500 / 1,500 / 3,000 / 6,000) |
| 단판 도달 | 배경 테마 6종 | 도달 레벨 (3 / 5 / 7 / 9 / 12) |

### 14-5. 구현

`game/config/themes.ts` — 테마 정의(하늘·지면·장식·입자·**림 색**·해금 레벨).
스킨과 마찬가지로 **게임 로직은 변경 없다.** 렌더 레이어만 테마를 읽는다.
테마도 **순수 외형**이며 낙하 속도·판정에 영향을 주지 않는다.

## 16. 벡터 추출로 전환 (2026-09-15)

아이템 아트를 **직접 그리지 않고 레퍼런스에서 추적**한다.
`docs/cute-hand-drawn-fruit-set-vector….avif`를 `potrace`로 벡터화했다.

### 16-1. 방법

1. 4×5 격자로 셀 분할 (경계 6px 인셋)
2. 셀 경계에 **닿는** 덩어리는 버린다 — 인접 셀 조각 제거.
   닿지 않는 작은 덩어리(잎·씨·껍질)는 **남긴다**
3. 비-흰색 픽셀을 주요 색 최대 6개로 군집 → 레이어별 이진 마스크
4. 레이어마다 potrace (`turdsize` 12/3, `alphamax` 1.0)
5. 72×72 뷰박스에 비율 유지로 정규화
6. **바탕 레이어에만** 윤곽선 `#4A3A2A` 2.6

> ⚠️ potracer는 `blacklevel 0.5` **미만**을 '칠해짐'으로 본다.
> 마스크를 **반전해서** 넣어야 한다(`~mask`). 안 그러면 배경이 추적돼 사각형이 나온다.

산출물: `assets/items.svg` (심볼 10개)

### 16-2. 원본에서 바꾼 것 — 세 가지뿐

| 항목 | 원본 | 변경 | 이유 |
|---|---|---|---|
| 딸기 색 | `#FEAE98` | `#F2546B` | 하늘 배경에서 거의 안 보였다 |
| 돌멩이 | 감자 `#DD872B` | 회색 `#918D86` | 레퍼런스에 돌멩이가 없어 감자 형태를 빌렸다 |
| 윤곽선 | 없음 | `#4A3A2A` 2.6 | 레퍼런스는 흰 배경용 (§15-3) |

윤곽선은 **추적된 경로를 그대로 따라간다.** 매끈한 선이 아니라 원본의 삐뚤빼뚤한 실루엣을
타고 흐르므로 손그림 느낌이 유지된다.

### 16-3. ⚠️ 수박 형태 축 변경 — "최대 원" → "삼각 조각"

레퍼런스의 수박은 통짜가 아니라 **삼각 조각**이다. §4의 형태 축을 고친다.

| | 통짜 (이전) | 조각 (레퍼런스) |
|---|---|---|
| 실루엣 | 원 — 사과·귤·복숭아와 같은 계열 | **삼각형 — 세트에서 유일** |
| 작을 때 | 줄무늬가 뭉개지면 초록 공 | 삼각형은 크기와 무관 |
| 흑백 | 구분 어려움 | 즉시 구분 |

원형 계열이 여섯 개나 되던 세트에서 **삼각형이 하나 생긴 것**은 구분에 큰 이득이다.

### 16-4. 나뭇가지

레퍼런스에 없어 같은 양식(평면 채색·굵은 선·손맛 곡선)으로 직접 그렸다.
**10종 중 유일하게 추적이 아닌 항목**이므로, 나란히 놓고 이질감이 없는지 주기적으로 확인한다.

## 17. 에셋 확정 — 과일 16 · 방해물 2 · 스킨 5 (2026-09-15)

### 17-1. 추적 설정 보완

첫 추적에서 형태가 불안정했던 것들을 고쳤다.

| 증상 | 원인 | 해결 |
|---|---|---|
| 포도 가지 끊김 | 얇은 구조가 `turdsize`에 걸려 제거 | **3배 업샘플 후 추적** |
| 복숭아 우측 직선 | `alphamax 1.0` — 코너로 판정 | `alphamax` **1.334**(최대 곡선화) |
| 곡선이 거침 | `opttolerance 0.22` 느슨함 | **0.12** |
| 수박 하단 껍질 잘림 | 껍질이 분리 덩어리라 제거 | 경계에 **닿는** 덩어리만 제거 |
| 레몬에 파편 | 옆 칸 조각이 셀 안까지 들어옴 | 주 덩어리 밖 작은 조각 제거 |

**업샘플링이 가장 효과적이다.** 원본이 칸당 90px라 얇은 줄기·씨가 1~2px였는데,
3배로 키우면 곡선이 매끄러워지고 작은 요소가 살아남는다.

### 17-2. 과일 16종 — 해금 순서는 실루엣 기준

둥근 계열(사과·귤·복숭아·자몽·키위)이 연달아 풀리지 않게 벌린다.

```
Lv1  사과 · 귤        Lv6  배          Lv11 블루베리
Lv2  바나나           Lv7  체리        Lv12 아보카도
Lv3  딸기             Lv8  레몬        Lv13 키위
Lv4  포도             Lv9  파인애플    Lv14 자몽
Lv5  수박             Lv10 복숭아      Lv15 사과 단면
```

### 17-3. ⚠️ 활성 풀 상한 — `ACTIVE_FRUIT_CAP = 8`

**해금된 과일을 전부 스폰 풀에 넣지 않는다.** 16종이 동시에 떨어지면 시각적 소음이 과해져
"타깃을 찾는 것"이 아니라 "화면을 훑는 작업"이 된다.

`items.ts`의 `activeFruits(level)`이 **최근 해금분 8종만** 반환한다.
레벨이 오르면 오래된 과일이 빠지고 새 과일이 들어와, 화면은 계속 바뀌지만 **복잡도는 일정**하다.

### 17-4. 고양이 스킨 5종

고양이 레퍼런스(457×360)는 격자가 어긋나 있어 **연결 덩어리 탐색**으로 20마리를 분리했다.
정면·직립 5마리를 골라 바구니를 얹었다 — 치즈 · 회색 · 흰둥이 · 삼색이 · 까망이.

바구니는 전 스킨 공통 부품이며, **머리 위에 얹히되 귀를 가리지 않는** 크기로 조정했다
(§13-2의 판정선 규칙 유지).

### 17-5. ❓ 주인공 종을 정해야 한다

레퍼런스에 고양이만 있어서 스킨이 **고양이 품종**이 됐다.
원래 계획(다람쥐·토끼·너구리·곰)은 각각 레퍼런스가 필요하다.

게임 이름이 "도토리 숲 바구니"인데 고양이가 도토리를 줍는 건 어색하다. 둘 중 하나:
- **(가)** 이름을 고양이에 맞게 바꾼다
- **(나)** 다람쥐 레퍼런스를 구해 기본 캐릭터로 쓰고, 고양이는 스킨으로 둔다
