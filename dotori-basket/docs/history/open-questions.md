# 미검증 · 미결 항목

#### ⚠️ 여기서부터는 봇으로 검증할 수 없다

낙하 2.0초 빌드에서 봇은 11초 만에 죽었다. **100ms 폴링 봇에게는 회피 판단에 3틱밖에
없기** 때문이다(2.5초로 되돌린 뒤에도 사람보다 불리한 건 같다). 사람보다 현저히 불리한 조건이라, 이 숫자에 맞춰 더
조정하면 봇에 과적합된다. **`slackCorrectGaps` · `recipesPerLevel` · 실패 시 진행도 리셋
세 가지는 사람 플레이로 확정해야 하며, 프로토타입 튜닝 패널에 슬라이더/토글로 열어 두었다.**

### 14-6. ⚠️ 아직 검증되지 않은 것

- **Lv4 이상 미검증** — 방해물(돌멩이·나뭇가지)은 Lv4부터, 수박·배·체리는 Lv5~7부터 등장한다.
  봇이 Lv3까지만 도달해 **해당 구간은 코드 경로만 있고 실측이 없다**.
- **Lv8 이후 무한 구간 미검증** — 아트가 8종에서 멈추므로 프로토타입 풀은 Lv7에서 고정된다.
  `items.ts`의 레몬 이후 8종은 그림이 없다.
- **framer-motion 경합**(§6)은 여전히 설계 추론이다. 프로토타입은 순수 RAF + CSS transform으로만
  돌았고 framer-motion을 쓰지 않았다.
- **실기기 미검증** — §8 웹뷰 항목은 공개 스펙 기반이다. 대상 앱의 웹뷰 설정(`WKWebView` pinch
  처리, `WebViewAssetLoader` 사용 여부 등)에 따라 달라질 수 있다.
- **게임성 수치**(점수 10/50, 콤보 ×3.0, 시작 HP 3, 즉시 스냅의 체감)는 플레이 없이 판단 불가다.

### 17-5. ❓ 주인공 종을 정해야 한다

레퍼런스에 고양이만 있어서 스킨이 **고양이 품종**이 됐다.
원래 계획(다람쥐·토끼·너구리·곰)은 각각 레퍼런스가 필요하다.

게임 이름이 "도토리 숲 바구니"인데 고양이가 도토리를 줍는 건 어색하다. 둘 중 하나:
- **(가)** 이름을 고양이에 맞게 바꾼다
- **(나)** 다람쥐 레퍼런스를 구해 기본 캐릭터로 쓰고, 고양이는 스킨으로 둔다
