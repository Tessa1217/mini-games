### 2-1. ⚠️ 컨트롤 바가 세로로 분리된 이유 (밸런스에 영향을 준 결정)

버튼을 다람쥐 **좌우**에 두려 했으나, 5레인이 전체 폭을 쓰므로 레인 0·4에 있는 다람쥐와
**46px 겹친다**. 세로로 분리하는 수밖에 없고, 그만큼 판정선이 올라간다.

→ `catchLineY` **540 → 500**.

> ⚠️ 이어지는 "`baseFallSpeedPxPerSec` 180 → 167"은 **두 리비전 stale**이다.
> rev.6·rev.7을 거쳐 현재 값은 **200**(낙하 2.5초)이다. 원문은 `history/rev5-review.md`.
(500/3.0), `sameLaneMinGapPx` **190 → 175**. 밀도 곡선은 그대로다(2.00 → 4.86, 재검증 완료).

**디자인이 밸런스 수치를 바꾼 사례**이므로 기록해둔다. 앞으로도 레이아웃 변경 시
`catchLineY`가 바뀌면 `baseFallSpeedPxPerSec`를 같은 비율로 보정해야 낙하시간이 유지된다.

### 2-2. 스케일링

```
scale = min(viewportW / 360, viewportH / 640)     ← contain
```
19.5:9 같은 긴 화면에서는 위아래 여백이 생기는데, **레터박스를 보이지 않게** 한다 —
컨테이너 뒤에 같은 하늘/잔디 그라디언트를 깔아 화면 끝까지 흐르게 한다.
`cover`로 잘라내면 판정선(y500 고정)이 화면 밖으로 나갈 수 있으므로 쓰지 않는다.

safe-area는 논리 좌표 **밖**에서 처리한다 — 컨테이너에 `padding: env(safe-area-inset-*)`.
논리 좌표 안에 넣으면 기기마다 판정선 위치가 달라진다.
