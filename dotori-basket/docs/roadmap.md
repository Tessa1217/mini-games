# 개발 페이즈 · 리스크

## 11. 개발 페이즈 / 리스크

| 페이즈 | 내용 | 완료 기준 |
|---|---|---|
| **P0 셋업** | Next 스캐폴딩, 정적 export, 논리 좌표계, 고정 타임스텝 루프, `platform/` | 빈 스테이지 + FPS 카운터 |
| **P1 조작** | 레인 5분할, 레인 스냅 이동, 키보드 + 좌우 버튼(홀드 repeat), 웹뷰 CSS | **실기기에서 조작 확인** |
| **P2 낙하·판정** | 레인 스포너(+**레인 최소 간격**은 여기부터 필요), 낙하, 라인 통과 판정, 오브젝트 풀 | 플레이스홀더로 "받기" 동작 |
| **P3 규칙** | 레시피 큐·타이머, 판정 3종, HP·무적, 점수·콤보 | 게임이 "게임"이 됨 |
| **P4 진행** | 레벨업·해금, 방해물, 게임오버·재시작, 최고 점수 | 완주 가능한 빌드 |
| **P4.5 계측** | ⭐ **헤드리스 밸런싱 시뮬레이터** — 봇 정책(탐욕적 정답 추적 + 오답 회피)으로 N판 자동 플레이 후 평균 도달 레벨·타이머 만료율·**규칙별 발동 횟수**·밀도 실측을 리포트 | 죽은 노브 0건 확인 |
| **P5 연출** | 디자인 에셋 교체, framer-motion 연출 | 무드 완성 |
| **P6 QA** | 실기기(iOS/Android), 성능 프로파일, 접근성 | 릴리스 후보 |

| 리스크 | 영향 | 대응 |
|---|---|---|
| React 리렌더로 프레임 드랍 | 모바일 플레이 불가 | `arch/stack.md`를 **P0부터** 강제 (나중엔 전면 수정) |
| framer-motion으로 낙하 구현 | 판정 불가, 구조 붕괴 | `arch/stack.md` 역할 분리를 설계 원칙으로 고정 |
| 버튼 홀드 시 `pointercancel` 누락 | 다람쥐가 안 멈춤 | `rules/input.md`, P1 실기기 검증 항목 |
| 스포너가 피할 수 없는 배치 생성 | 억울한 피해 → 이탈 | `rules/spawner.md` 보장 규칙 4종 (특히 동시 통과 상한) |
| 레시피 타이머가 상시 압박이 됨 | "피하는 판단"이라는 핵심 재미가 죽음 | 넉넉하게 배분(`rules/recipe.md`), 플레이테스트에서 만료 빈도 측정 |
| 웹뷰 제스처 충돌 | 조작 불가 | P1 실기기 우선 검증. 데스크탑만 믿지 않는다 |
| 난이도 곡선 실패 | 재미 저하 | 수치 전부 `balance.ts` 단일 파일 |
| **죽은 노브**(설정을 바꿔도 게임이 안 바뀜) | 밸런싱이 헛돎 | rev.4에서 실제로 3건 발생했다. **사람이 플레이해서는 절대 안 보인다** → P4.5 시뮬레이터로 규칙 발동 횟수를 계측 |
| 규칙 경로가 한 번도 실행되지 않은 채 배포 | 밀도를 올리는 순간 미실행 코드가 처음 활성화되며 터짐 | 동일 — P4.5에서 발동 카운터 확인 |
